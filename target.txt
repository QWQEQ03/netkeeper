三、OSPF

实现基于链路 ospf_weight 的 OSPF 路由计算。

要求：

1. 使用 Dijkstra 算法或 NetworkX 等价实现
2. 对每个源节点和目的节点计算：
   - 最短路径代价
   - 所有满足最短代价的下一跳
3. 返回统一的转发表，例如：

forwarding_table[source][destination] = {
    "cost": 10,
    "next_hops": ["R2", "R3"]
}

4. 不要只返回一条 shortest_path，必须保留所有 ECMP 下一跳
5. 对不可达节点要有明确表示
6. 支持无向拓扑，内部允许扩展为双向链路
7. 支持链路故障后重新计算路由

四、ECMP

实现 Equal-Cost Multi-Path。

要求：

1. 当存在多个等价下一跳时，流量默认平均分配
2. 例如某源到目的有两个等价下一跳，100 单位流量应各分配 50
3. 分流过程需要递归或按拓扑顺序传播，直到到达目的节点
4. 必须防止路由环路和无限递归
5. 对浮点误差设置合理容差
6. 保存每个源宿流量经过的边以及对应流量

输出示例：

flow_paths[(src, dst)] = {
    (u1, v1): traffic_amount,
    (u2, v2): traffic_amount
}

五、简化 BGP

这一阶段不实现完整 RFC BGP，只实现明确、可测试的简化路径选择模型。

定义 BGPRoute 数据结构，至少包括：

- prefix
- next_hop
- local_preference
- as_path
- med
- origin_router
- learned_from
- igp_cost_to_next_hop

路径选择顺序：

1. Local Preference 越大越优
2. AS Path 越短越优
3. MED 越小越优
4. 到 next hop 的 IGP cost 越小越优
5. 最后使用稳定、确定性的 router ID 或字符串排序打破平局

要求：

- 为每个路由器和 prefix 选择最佳 BGP 路由
- BGP 选出的 next hop 应通过 OSPF/IGP 转发表继续转发
- 提供少量人工构造的测试拓扑验证 BGP 选择顺序
- 在 README 中明确说明这是简化 BGP，而不是完整协议实现

六、流量矩阵

实现 TrafficMatrix 类。

支持至少两种输入：

1. CSV 文件
2. Python/NumPy 矩阵

CSV 可以采用长表格式：

source,destination,demand
R1,R5,100
R2,R6,50

要求：

- 验证源和目的节点是否存在
- 不允许负数流量
- source == destination 时可忽略或明确处理
- 支持随机生成流量矩阵
- 随机种子必须可配置，保证实验可复现

七、流量传播和指标

根据 OSPF、BGP 和 ECMP 转发表传播流量。

计算每条链路：

- total_load
- utilization = total_load / capacity

同时计算：

- maximum_link_utilization
- average_link_utilization
- overloaded_links
- unreachable_demands
- dropped_traffic，可先只处理链路不可达导致的流量丢失

第一阶段暂时不要实现复杂队列模型，但数据结构应保留 queue_length、loss_rate 等字段，方便以后扩展。

九、测试要求

必须先使用人工小拓扑写测试，不要只在 Topology Zoo 大拓扑上验证。

至少包含以下测试：

1. 单一路径拓扑：
   R1 -- R2 -- R3
   验证最短路径和流量传播

2. ECMP 菱形拓扑：
       R2
      /  \
   R1     R4
      \  /
       R3
   所有链路权重相同，验证 R1 到 R4 的流量平均分配

3. 非等价路径：
   修改其中一条链路权重，验证不再分流

4. 链路故障：
   删除或禁用一条链路，验证重新选路或不可达

5. BGP：
   构造多个候选路由，分别验证 Local Preference、AS Path、MED 和 IGP cost 的优先级

6. 流量守恒：
   无丢包且目的可达时，进入网络的总流量应与到达目的的总流量一致

7. 最大链路利用率：
   使用人工计算结果与程序结果进行比较
