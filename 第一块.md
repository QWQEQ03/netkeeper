```
NetworkScenario
  → UnifiedNetworkEnvironment.reset()
  → evaluated NetworkSnapshot + AgentObservation
  → UnifiedNetworkEnvironment.step(snapshot, JointAction, events)
      → Event scheduler
      → action validation / immutable NetworkConfiguration update
      → deterministic OSPF/BGP/performance simulation
      → policy + versioned metrics evaluation
      → RewardBreakdown
      → StepResult + next NetworkSnapshot
```

## 最终 Schema

新增并导出：

- `NetworkScenario`
- `AgentObservation`
- `AtomicAction`
- `JointAction`
- `RewardBreakdown`
- `StepResult`

`AtomicAction` 支持：

```
AtomicAction(
    agent_id="ospf" | "bgp" | "performance" | "baseline" | "llm",
    parameter_type="ospf_weight" | "local_preference" | ...,
    target={"link_id": "..."} | {"router_id": "...", "prefix": "...", "next_hop": "..."},
    mode="set" | "delta" | "no_update",
    value=...,
    mask=True,
)
```

约束：

- 同一 `target + parameter_type` 不可重复修改。
- `no_update` 不可携带值，不改变 configuration version。
- action batch 任一项非法，整个 batch 不应用配置修改。
- Snapshot ID 不匹配会被拒绝为 `stale_action`。
- `StepResult` 含 previous/next Snapshot、观测、奖励分解、终止状态、配置 diff、指标和结构化错误。

## reset/step 示例

```
env = UnifiedNetworkEnvironment()
snapshot, observation = env.reset(scenario, seed=7)

action = JointAction((
    AtomicAction(
        "ospf",
        "ospf_weight",
        {"link_id": "L:R0--R1:0"},
        "set",
        10,
    ),
), snapshot_id=snapshot.snapshot_id)

result = env.step(snapshot, action)
```

固定执行顺序：

```
events
→ event 后 observation
→ action validation
→ configuration update
→ OSPF/BGP recomputation
→ traffic propagation
→ policy/metrics evaluation
→ reward calculation
→ new snapshot
```

`terminated` 不会因 Policy Consistency=1 自动触发；只有显式设置 `scenario.target_mlu` 且可行策略一致、MLU 达标、没有待执行恢复事件时才终止。达到 `max_steps` 仅设置 `truncated=True`。
