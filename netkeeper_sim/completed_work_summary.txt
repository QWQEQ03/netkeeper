NetKeeper Sim 已完成内容记录
============================

记录目的
--------
本文档用于记录当前 NetKeeper Sim 项目已经完成的内容，方便后续继续复现 NetKeeper 论文时快速了解当前进度。


一、项目定位
------------
当前项目：

  netkeeper_sim/

项目定位是 NetKeeper 论文复现所需的轻量级网络仿真与多智能体强化学习原型。当前已经包含：

  1. 确定性网络仿真内核
  2. Topology Zoo GraphML/GML 加载
  3. OSPF/ECMP 路由
  4. 简化 BGP 路径选择
  5. 流量矩阵和流量传播
  6. Policy Consistency、Maximum Link Utilization、Traffic Shift 三个指标
  7. 多智能体 RL 环境适配层
  8. 共享 Graph Transformer encoder
  9. OSPF/BGP/Performance decentralized actors
  10. Centralized critic
  11. COMA baseline、actor loss、critic TD loss
  12. Replay buffer、epsilon-greedy、target critic、debug trainer、checkpoint

当前仍明确不实现：

  1. 完整 BGP 协议
  2. BGP 会话、报文、withdraw、route reflection、community、真实策略语言
  3. Mininet、FRRouting、Containerlab 或真实设备部署
  4. LLM、LangChain、DSL 或意图翻译
  5. 真实队列、真实丢包或时延仿真
  6. 论文级大规模实验复现和完整训练结果复现

reward：

  R_pol = K * policy_consistency + stationary_reward + dynamic_reward
  R_res = K * ((1 - normalized_load) + (1 - traffic_shift))

  R_OSPF = R_pol + R_res
  R_BGP = R_pol
  R_PERF = R_res

已实现：

  1. reward_mode = "paper"
  2. reward_mode = "normalized"
  3. repeated-action penalty：连续两步完全相同 joint action，-1
  4. dynamic reward：逐策略从不满足到满足 +1，从满足到不满足 -1
  5. normalized 模式下 maximum_link_utilization 可裁剪，避免 MLU > 1 造成奖励失控

step 时序：

  1. 保存更新前 forwarding snapshot
  2. 生成并校验 action mask
  3. 应用联合动作
  4. 重新计算 OSPF
  5. 重新计算 BGP
  6. 传播流量
  7. 计算策略一致性
  8. 计算 maximum link utilization
  9. 使用更新前 snapshot 与更新后 snapshot 计算 traffic shift
  10. 构造新 state/observation
  11. 计算 rewards
  12. 判断 terminated/truncated

Critic 设计：

  1. Critic 使用独立 SharedGraphTransformerEncoder
  2. Critic 不与 actor 共享参数
  3. 对指定 agent、parameter、entity 输出所有候选动作 Q-values

输出形状：

  Q_i,k: [num_entities, 64]

debug 参数量：

  Critic params: 90,944

COMA baseline：

  baseline = sum_a pi_i,k(a | o_i) * Q_i,k(s, a)
  advantage = Q_i,k(s, selected_action) - baseline
  advantage = advantage * entity_mask

已确认：

  1. baseline 对所有候选动作求期望
  2. 无效 entity 不进入 baseline
  3. actor 概率来自 masked logits
  4. selected Q 使用 gather
  5. advantage 默认 detach，避免 actor loss 反向更新 critic
  6. selected action 越界或 valid entity 上为 -1 时会显式报错，避免 silent clamp bug

Actor loss：

  -mean(log pi(selected_action) * advantage.detach())

Critic target：

  target = reward + gamma * (1 - done) * target_Q_next

说明：

  论文对 critic target 和 loss 的完整公式描述有限，当前实现使用标准一阶 TD 目标作为工程假设。

Critic loss：

  默认 Huber loss
  支持 MSE

Target critic：

  1. target_critic 参数 requires_grad=False
  2. target critic forward 在 no_grad 中执行
  3. 默认每 16 step hard update
  4. 支持可配置 tau soft update
  5. tau 不声称来自论文原值

Replay Buffer：

  capacity = 100
  batch_size 默认 = 16
  debug batch_size = 2
  使用 list batch 支持不同规模图
  不强行 padding 到固定最大拓扑
  支持 seed

Epsilon-greedy：

  initial epsilon = 1.0
  final epsilon = 0.01
  decay = 0.99 per timestep

规则：

  1. 训练阶段以 epsilon 概率从合法动作随机采样
  2. 否则按 actor Categorical 分布采样
  3. eval 阶段 deterministic argmax
  4. 无效 entity 始终输出 -1，映射为 no-op，不会被环境执行

十、审查中发现并修复的问题
--------------------------

1. 重复 source-destination demand 覆盖 flow_paths

修复：

  改为对相同 flow_key 的边流量进行聚合累加。


2. BGP 出口 IGP 不可达时丢失 prefix 上下文

修复：

  propagate_bgp_traffic 中将不可达记录恢复为原始 prefix。


3. COMA selected action silent clamp bug

问题：

  selected action 为 -1 或越界时，gather 前使用 clamp_min(0) 可能导致 valid entity 上的非法动作被静默当成动作 0。

修复：

  在 COMA baseline、selected_log_probabilities、critic_loss 中增加 selected action 范围校验。


4. TD target 无效 next entity bootstrap 表达不够明确

修复：

十一、当前设计假设与限制
------------------------

1. Topology Zoo 拓扑按无向图处理
2. 无向链路可双向转发
3. OSPF 使用静态 ospf_weight
4. ECMP 按下一跳数量等比例分流
5. 平行链路在 OSPF 路由计算中按最小权重折叠
6. 等权平行链路在负载统计中平均分担
7. Topology Zoo 缺失仿真属性用配置默认值补齐
8. 默认 capacity、bandwidth 等不代表真实测量值
9. BGP 是简化路径选择，不是完整协议
10. Performance Agent 当前控制 bandwidth、capacity、queue_length，但真实队列和丢包模型尚未实现
11. GraphTrans 是工程近似实现，不是论文源码级复刻
12. Network Sketch 特征是可解释工程编码，不是论文未公开的 20 维原始编码
13. Critic target 使用标准一阶 TD 目标，是工程假设
14. 当前训练循环是 debug/smoke 级别，不代表论文实验结果
15. 系统 Python 环境未安装 torch/PyG；网络和训练测试通过本地 .venv 的 torch/PyG 运行
